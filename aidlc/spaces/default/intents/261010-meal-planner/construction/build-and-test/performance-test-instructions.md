# 性能テスト手順

## 対象と目標

性能要件の実測対象は、NFR2.1〜NFR2.3、詳細要件の U1-NFR2.1〜U1-NFR2.5、および献立・買い物リストの応答時間である。目標は次のとおり。

| 対象 | 目標 |
|---|---|
| 候補取得・一覧取得 | 料理 200 件以下、起動済み状態で p95 <= 500 ms |
| 保存・お気に入り・選択 | 起動済み状態で p95 <= 500 ms |
| 登録・ログイン | p95 <= 1 s |
| 買い物前の最初の候補 | 4G 相当の通信で画面表示まで <= 2 s（起動済み） |
| 献立提案 | 200 件以下の条件で結果表示 <= 3 s |
| 買い物リスト作成 | 結果表示 <= 1 s |
| コールドスタート | 最初の応答 <= 3 s、最初の候補表示まで <= 5 s。15分以上空けた試行を5回以上 |

## ローカルでの再現手順

1. `data/seed-dishes.json` の30件を使い、必要に応じてテスト専用データで料理数を200件以下にする。
2. `npm run build` 後に `npm start` でローカル本番モードを起動する。
3. 認証済みのテストデータを用意し、候補、一覧、保存、ログイン、献立、買い物リストを各100回以上呼び出す。
4. 平均ではなく p50、p95、p99、RPS、エラー率を記録する。レスポンス時間と画面表示時間は分ける。
5. 4G相当の通信制限を適用した実ブラウザで、買い物前の最初の候補表示を測る。
6. 各測定に、Node.js、ブラウザ、料理件数、DB方式、環境変数、測定日時を添える。

## 今回の実行範囲と結果

今回実行したのは、性能試験そのものではなく、性能試験の前提確認である。

- `npm run build`: 成功。Next.js の本番バンドルとページ生成を確認した。
- `npm start` + `curl --fail --silent --show-error --max-time 10 -D - http://localhost:3000/healthz -o /tmp/meal-planner-healthz.body`: `HTTP/1.1 200 OK`。
- Vitest 全体: 719 tests passed。テスト実行時間は Vitest 出力上 14〜33秒だが、これはテストスイートの実行時間であり、APIや画面のp95性能値ではない。

k6、Artillery、実ブラウザの4G制限、200件データの負荷、15分待機を伴うコールドスタートは実行していない。性能要件の Actual は推測せず `Unverified` とする。後続の performance-validation stage はこの scope では skip のため、AWSや検証環境を作らずに今回のゲートを完全合格にすることはできない。

## 判定

各目標は、測定データがない限り pass としない。p95、画面表示時間、コールドスタートのいずれかが欠ける場合は `Unverified` と記録する。外部サービスやAWSを使った負荷試験は、明示的な承認なしに実施しない。
