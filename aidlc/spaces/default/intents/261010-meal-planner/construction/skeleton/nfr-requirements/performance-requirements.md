# 性能と画面の要件：U1 最小の通し版

U1 の性能の目標と、画面（スマートフォン）の使いやすさの目標です。各行の ID は、要件（`requirements.md`）の NFR を U1 向けに細かくしたものです。

## 根拠（Sources）

- [Q4] サーバーの応答は 95% のリクエストで 500 ミリ秒以内、最初の候補の表示は 2 秒以内（4G 相当、料理 200 件以下）
- [Q9] 登録は数十人、同時に使うのは 10 人程度
- [Q10] iPhone の Safari と Android の Chrome の、最新から 2 つ前までの版
- [scope] `requirements.md` NFR1、NFR2、`rules.md` BR4.10

## 画面とアクセシビリティ（NFR1）

| ID | 要件 | 測り方 |
|---|---|---|
| U1-NFR1.1 | 画面幅 360px 以上の縦向きで、U1 のすべての操作（登録、ログイン、保存、候補、お気に入り、編集・削除）が横スクロールなしで行える | 360px の画面で、全画面を手で確認する |
| U1-NFR1.2 | ホームから「買い物前」の画面まで、2 回以内の操作で開ける（BR4.10） | 操作回数を数える |
| U1-NFR1.3 | 保存は、URL と料理名の入力から完了まで、1 画面で行える（BR3.13） | 画面遷移の数を確認する |
| U1-NFR1.4 | 文字と背景のコントラスト比は 4.5:1 以上。操作要素に、読み上げ用のラベルを付ける | コントラストの自動チェックと、手での確認 |
| U1-NFR1.5 | スワイプでできる操作は、すべてボタンでもできる（BR4.9） | ボタンだけで、候補を最後まで見終える |
| U1-NFR1.6 | 対応するブラウザは、iPhone の Safari と Android の Chrome の、最新から 2 つ前までの版。パソコンは、最新の Chrome、Safari、Edge で表示が崩れない（Q10 A） | 対象の端末で、主要な操作を確認する |

## 応答時間（NFR2）

| ID | 要件 | 測り方 |
|---|---|---|
| U1-NFR2.1 | グループの料理が 200 件以下のとき、候補の取得（最初の 1 件）と一覧の取得は、サーバーが 95% のリクエストで 500 ミリ秒以内に返す（Q4 A） | 負荷をかけずに 100 回以上取得し、95 パーセンタイルを測る |
| U1-NFR2.2 | 通常の通信（4G 相当）で、「買い物前」の画面を開いてから最初の候補が出るまで 2 秒以内 | 通信を 4G 相当に制限して、画面を開き直して測る |
| U1-NFR2.3 | 料理の保存、お気に入りの付け外し、「これにする」は、サーバーが 95% のリクエストで 500 ミリ秒以内に返す | U1-NFR2.1 と同じ |
| U1-NFR2.4 | ログインと登録は、パスワードの変換に時間をかけるため（U1-NFR3.1）、サーバーが 95% のリクエストで 1 秒以内に返す | U1-NFR2.1 と同じ |
| U1-NFR2.5 | しばらく使わなかったあとの最初のリクエスト（サーバーレスの立ち上がりの遅れ、暫定）は、サーバーが 3 秒以内に返す。「買い物前」を開いてから最初の候補が出るまでは、立ち上がりの遅れを含めて、5 秒以内とする（暫定） | 15 分以上あけてから開き直す測定を、5 回以上行い、すべてが基準内か確かめる |

### 補足

- サーバーレス（Q3 B）では、しばらく使わなかったあとの最初のリクエストが遅くなることがある（立ち上がりの遅れ）。家族向けの小さなアプリでは、これが普通の体験になりうる。そのため、U1-NFR2.1、U1-NFR2.3、U1-NFR2.4 の 95 パーセンタイルの計測は、すでに起動している状態で行い、立ち上がりの遅れは別の数値（U1-NFR2.5）で目標を置く。U1-NFR2.2 の 2 秒の測定は、起動している状態で、5 回以上行う。
- 「常に 1 つ起動しておく」案は、Q3 B の理由（使わない間の費用が小さい）と食い違うため、置かない。U1-NFR2.5 を守れない場合は、費用との兼ね合いを利用者に確認してから、Infrastructure Design で方式を決める。
- 初期データ 30 件と利用者の保存を合わせて 200 件以下の範囲で測る。200 件を超える場合の目標は、置かない。

## Assumptions & Open Questions

- [assumption] 500 ミリ秒（95%）は、2 秒の目標のうち、画面の描画と通信に 1.5 秒を残す配分として置いた（Q4 A）。
- [assumption] ログイン・登録の 1 秒（U1-NFR2.4）は、質問では聞いていない。パスワードの変換を意図的に遅くするため、他より長く置いた。
- OQ1 立ち上がりの遅れが U1-NFR2.2 を守れるかは、実測が必要。Build and Test で測り、守れなければ Infrastructure Design の工夫を足す。
