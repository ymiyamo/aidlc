# 信頼性と品質の要件：U1 最小の通し版

## 根拠（Sources）

- [Q5] バックアップは取らない
- [Q6] 可用性の目標は置かない。「まずは動かすを優先」
- [F1 B] 本番でも、バックアップも可用性の目標も置かない。データが消えるリスクを承知する
- [F2 A] 止まったこと・エラーが増えたことの通知は行う
- [scope] `requirements.md` NFR4、NFR5、NFR6、`rules.md` BR3.12（初期データの補完）、BR3.9（論理削除）

## 受け入れたリスク

| ID | リスク | 受け入れの根拠 |
|---|---|---|
| RISK-1 | バックアップを取らないため、データベースが壊れたり、誤って消したりしたとき、**保存した料理やグループのデータは戻らない**。本番でも同じ（F1 B） | 利用者が F1 B を選択（本番でも、データが消えるリスクを承知のうえで受け入れた）。まずは動かすことを優先する |
| RISK-2 | 可用性の目標がないため、止まっていても「違反」にはならない。止まったことは通知で気づく（U1-NFR4.6） | 利用者が Q6、F1 B を選択 |

## 信頼性

| ID | 要件 | 関連ルール |
|---|---|---|
| U1-NFR4.1 | 登録したデータ（グループ、料理、お気に入り、「選んだもの」）は、再ログイン後も、別の端末でも、失われない（通常の保存の範囲。壊れたときの復元は U1-NFR4.3 のとおり対象外） | — |
| U1-NFR4.2 | データの変更は、中途半端な状態を残さない。グループの作成（Household と Member）は、どちらかだけが残る状態にしない | BR2.2 |
| U1-NFR4.3 | バックアップと復元は、この版では行わない（Q5 C、F1 B）。データベースが提供する標準の保護（サービスが自動で行うもの）があっても、それに頼る約束はしない | RISK-1 |
| U1-NFR4.4 | 可用性の数値の目標（99% 等）は、置かない（Q6 X、F1 B） | RISK-2 |
| U1-NFR4.5 | 料理を削除しても、データは残す（論理削除）。誤って削除した料理を、運用者が手作業で戻せる余地を残す。U1 に復元の画面はない | BR3.9 |
| U1-NFR4.6 | 止まったこと、エラーが増えたことは、通知で気づけるようにする（`observability-requirements.md` U1-NFR4.14、U1-NFR4.15） | F2 A |
| U1-NFR4.7 | （推奨・任意。出荷の条件ではない）利用者が望むとき、いつでもバックアップと可用性の目標を置き直せる。置き直すときは、新しい要件として追加する | RISK-1、RISK-2 |

| ID | 要件 | 関連ルール |
|---|---|---|
| U1-NFR5.1 | YouTube・Instagram のデータは取得しない。利用者が入力した URL を、リンクとして扱うだけにする | BR3.3 |

| U1-NFR5.3 | U1 は、画像の生成や、メールの送信など、外部のサービスを呼ばない。外部の障害の影響を受けない | — |

|---|---|---|

## 保守性とテスト

| ID | 要件 |
|---|---|
| U1-NFR6.1 | 通し版（U1）そのものには、行カバレッジ 80% の下限は適用しない。通し版の後に追加・変更するコードに適用し、CI でテストを実行してからマージする（`team.md`） |
| U1-NFR6.2 | 言語標準の整形と lint（Prettier、ESLint）に従う。CI で失敗したらマージしない |
| U1-NFR6.3 | 通し版の最小範囲は、ログイン、URL と料理名の保存、買い物前の候補表示と次の候補へ進むこと。この範囲が端から端まで動くことを、検証コマンドで確かめる |
| U1-NFR6.4 | 通し版でも、他のグループのデータが見えないことと、同時操作で 1 件のままになること（U1-NFR7.4〜U1-NFR7.7）は、テストで確かめる（セキュリティと整合性は、カバレッジの免除の対象にしない） |

## Assumptions & Open Questions

- [assumption] U1-NFR6.4 は、質問では聞いていない。Q8（セキュリティ）と Q2（制約で守る）の回答から、テストを省かない最小の範囲を置いた。
- [assumption] U1-NFR4.5 の「運用者が手作業で戻せる余地」は、論理削除（ADR-008）の結果であり、新しい約束ではない。
- [decided] RISK-1 は、F1 B のとおり、本番でも承知のうえで受け入れた。本番前の再確認を出荷の条件にはしない（レビューの指摘を受けて、質問にない条件を取り下げた）。
