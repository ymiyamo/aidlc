# セキュリティ要件：U1 最小の通し版

U1 が守るべきセキュリティの要件です。U1 の範囲は、登録、ログイン、グループの範囲の確認、料理の入力です。ログインの失敗回数の制限とパスワードの再設定は U7 です。

## 根拠（Sources）

- [Q8] ログイン状態の Cookie は HttpOnly、Secure、SameSite。状態を変える操作は CSRF 対策。パスワードは時間のかかる専用の変換で保存
- [Q7] パスワード、メールアドレス、料理のメモをログに出さない
- [scope] `requirements.md` NFR3、`rules.md` BR1.1〜BR1.6、BR2.3、BR2.4、BR3.1、`decisions.md` ADR-005

## 認証

| ID | 要件 | 関連ルール |
|---|---|---|
| U1-NFR3.1 | パスワードは元の文字列を保存せず、時間のかかる専用の変換（bcrypt または argon2 相当）で保存する。変換の強さは、U1-NFR2.4（1 秒以内）を守れる範囲で、できるだけ強くする | BR1.3 |
| U1-NFR3.2 | ログイン状態の識別子は、推測できないランダムな値にする。Cookie には HttpOnly（スクリプトから読めない）、Secure（HTTPS でだけ送る）、SameSite（他のサイトからの送信では付かない）を設定する。有効期間は 30 日 | BR1.5 |
| U1-NFR3.3 | ログインの失敗は、メールアドレスとパスワードのどちらが違うかを区別しない。登録時のメールアドレスの重複も、登録済みかどうかを教えすぎない表示にする | BR1.2、BR1.6 |
| U1-NFR3.4 | ログインの失敗回数による制限（5 回で 15 分）は U1 では行わない。U7 で行う。それまでの間、通し版は一般には公開せず、検証環境の限られた利用者だけが使う。制限の手段（暫定）は、検証環境の入口を、チームの決まった利用者にだけ開けること（入口での認証など）。U7（ログインの失敗の制限）が完成する前に、本番を一般に公開しない。本番の手動承認（U1-NFR7.10）のときに、この条件を確認する | BR1.6 |

## 認可（グループの範囲）

| ID | 要件 | 関連ルール |
|---|---|---|
| U1-NFR3.5 | すべての業務リクエストは、リクエストの入口で、ログイン状態からグループを決める。画面から渡されたグループの値は信用しない | BR2.3、ADR-005 |
| U1-NFR3.6 | 他のグループのデータを指定されたら、「見つからない」として返す。存在の有無を教えない | BR2.4 |
| U1-NFR3.7 | データへの問い合わせは、必ずグループで絞る。グループで絞らない問い合わせを作らない。テストで、他のグループのデータが見えないことを、読み取りと書き込みの両方で確かめる | BR2.3、BR2.4 |

## 入力と出力

| ID | 要件 | 関連ルール |
|---|---|---|
| U1-NFR3.8 | すべての入力は、サーバー側で検証する（型、文字数、選択肢、タグ数、材料の行）。画面側の検証だけに頼らない | BR3.1〜BR3.5、BR1.1、BR1.2 |
| U1-NFR3.9 | 保存した URL をリンクとして開くのは、http または https だけ。それ以外の形（javascript: 等）は保存も表示もしない。リンクは新しいタブで開き、このアプリの情報を渡さない（noopener、noreferrer 相当） | BR3.1、BR3.3 |
| U1-NFR3.10 | 利用者が入力した文字列（料理名、メモ、タグ、材料）を画面に出すときは、画面を壊したり、スクリプトを実行させたりしない形で出す（出力のエスケープ） | BR3.2、BR3.5 |
| U1-NFR3.11 | 状態を変えるすべての操作（登録、ログアウト、保存、編集、削除、お気に入り、「これにする」、「外す」）に、CSRF 対策（なりすまし防止）を入れる | Q8 A |

## 通信と秘密情報

| ID | 要件 |
|---|---|
| U1-NFR3.12 | 通信は HTTPS だけ。HTTP でのアクセスは HTTPS へ移す |
| U1-NFR3.13 | データベースの接続情報などの秘密の値は、プログラムに書かず、環境の設定または秘密情報の管理の仕組みで渡す。リポジトリに入れない |
| U1-NFR3.14 | ログに、パスワード、メールアドレス、ログイン状態の識別子、料理のメモ、料理の URL を出さない（一覧の正本は `observability-requirements.md` の U1-NFR4.13） |
| U1-NFR3.15 | 初期データのファイルには、個人情報を入れない。ダミーの URL だけを持つ |

## 脅威の見立て（U1）

| 脅威 | 対策 |
|---|---|
| 他のグループのデータを見られる | U1-NFR3.5〜U1-NFR3.7 |
| なりすまし（他のサイトからの勝手な操作） | U1-NFR3.2、U1-NFR3.11 |
| パスワードの流出 | U1-NFR3.1、U1-NFR3.13 |
| 不正な URL による攻撃 | U1-NFR3.9、U1-NFR3.10 |
| パスワードの総当たり | **U1 では未対応**（U7 で制限）。U1-NFR3.4 のとおり、公開しない |

## Assumptions & Open Questions

- [assumption] パスワードの変換の方式は、bcrypt または argon2 相当の中から、コード生成で選ぶ。
- [assumption] U1-NFR3.4 の「通し版は公開しない」は、質問では聞いていない。ログインの制限が U7 まで無い間の、必要な約束として置いた。公開の時期は、Delivery Planning の順番（U7 は B4）に従う。
- OQ1 メール送信の確認なしで登録できる（BR1.4）ため、他人のメールアドレスで登録される可能性がある。通し版の範囲では許容する。公開前に見直す。
