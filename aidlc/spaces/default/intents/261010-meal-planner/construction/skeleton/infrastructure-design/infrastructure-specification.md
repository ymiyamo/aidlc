## 配置（Deployment）

| 項目 | 選択 | 理由 |
|---|---|---|
| 動かし方 | アプリ全体を 1 つの関数（Lambda 相当）に載せる。HTTPS の入口は、配信網（CloudFront 相当）と API の入口（API Gateway 相当）（Q3 A） | 全ユニット 1 アプリの方針。使わない間の費用が小さい |
| 画面の部品（静的ファイル） | 保管場所（S3 相当）に置き、配信網から配る | 関数の負荷と立ち上がりの遅れを減らす（NFR2.5） |
| ネットワーク | 関数とデータベースを、同じ仮想ネットワーク（VPC）の私的なサブネットに置く。外から直接データベースには届かない。入口は HTTPS のみ（NFR3.12） | データベースを公開しない |
| ストレージ | データベースのみ。ファイルの保管は U1 では不要（画像は U6） | 最小 |
| 環境 | 本番（production）と検証環境（staging）。同じ AWS アカウント、同じ構成のコード、設定だけ変える（Q4 A）。自分のパソコンでの動作確認用に、ローカル環境を別に持つ（Q7 A） | チームの方針 |
| IaC | AWS CDK（TypeScript）（Q1 A） | アプリと同じ言語 |
| 規模（サイズ） | 関数：メモリ 1024MB（暫定）、タイムアウト 15 秒。データベース：最小 0.5 容量単位から、最大 2 まで（暫定）。**停止はしない**（下限は 0.5。0 にして止めると、再開の遅れで U1-NFR2.5 を守れないため）。関数の同時実行は 10 に絞る（暫定）。費用は「費用の目安」を参照 | 数十人・同時 10 人（NFR7.1）。測って調整 |
| リージョン | 東京（暫定） | 利用者が日本。通信の遅れを小さく（NFR2.2） |
| ローカル環境 | データベースはコンテナで起動し、アプリは自分のパソコンで動かす。初期データ、ログイン、保存、候補の動作を確認できる（Q7 A） | 1st バージョンをすぐ触る |
| AWS への実際の作成 | **この段階では行わない**。構成をコードにするところまで。実際の作成・配布は、費用と取り消しにくさがあるため、別に利用者の承認を得てから行う | 安全のため |

### 検証環境の入口の制限（NFR3.4）

- **方式（1 つに決定）**：配信網に付ける小さな処理（CloudFront Functions 相当）で、共有の合言葉（Basic 認証）を確認する。合言葉を知らない人には、画面も API も届かない。合言葉は秘密情報に預ける。
- **抜け道の封じ**：API の入口は、配信網だけが付ける秘密の見出し（オリジンの秘密）を持つリクエストしか受けない。API の入口の直接の URL にアクセスしても、秘密の見出しがなければ拒否する。秘密の見出しの値は秘密情報に預ける。
- **本番にも同じ制限を既定で有効にする**（環境の設定 `publicRestricted`）。U7（ログインの失敗の制限）が完成するまで、`publicRestricted=true` のままにする。解除は、本番の手動承認とは**別の、明示の設定変更**（変更のプルリクエスト）で行い、そのレビューで U7 の完成を確認する。承認ボタンだけでは公開されない。
- 制限は環境ごとの設定として持つ（構成のコードは共通）。

### 死活確認の経路

- スケジュールは、配信網の公開 URL の `/healthz` を呼ぶ。`/healthz` は、入口の制限（合言葉）の**例外**とし、固定の応答（OK）だけを返す。データベースにも秘密情報にも触れない。
- `/healthz` は、秘密の見出しの確認は通す（配信網経由なので付く）。外から直接 API の入口を呼んでも拒否される。
- 立ち上がりの遅れの測定（U1-NFR2.5）の間は、この確認を止める。CI の検証環境の確認（流れ 4）は、測定の前後に行い、測定の最中には走らせない。

### 費用の目安（概算。実際に作る前に、利用者に確認する）

次の金額は、公開されている一般的な料金から私が概算したもので、**正確に確かめていない**。実際に作る前の承認で、最新の料金で見積り直す。

| 項目 | 概算（月、検証環境 1 つあたり） | 備考 |
|---|---|---|
| データベース（0.5 容量単位、停止なし） | 約 40〜50 ドル | 停止しないため、使わない間もかかる。止める設定（0）は、再開の遅れで NFR2.5 を守れない |
| 接続の束ね | 約 20 ドル前後 | 外す選択肢あり（OQ3） |
| 関数の外向き通信（Secrets とログへの経路） | 約 7〜10 ドル（VPC エンドポイント）。NAT を使うと約 30 ドル以上 | VPC エンドポイントを選ぶ |
| 関数、API、配信網、保管場所 | 数ドル | 利用が少ないため |
| 合計 | 約 70〜90 ドル | 本番を含めると約 2 倍 |

- 「使わない間の費用が小さい」という Q2 A の理由と、この金額は**合わない可能性がある**（データベースを止めない選択のため）。AWS に実際に作る前に、利用者に確認する事項とする。

## Assumptions & Open Questions

- [assumption] 質問では聞いていない暫定値：関数のメモリ（1024MB）、タイムアウト（15 秒）、同時実行 10、データベースの容量単位（0.5〜2）、リージョン（東京）、日本向けの配信、API の基本の制限、通知先（共有のメール）、検証環境の制限の方式（Basic 認証）、Secrets を起動時に読むこと、外向き通信の VPC エンドポイント。
- [decided] データベースは停止しない（下限 0.5）。理由：停止からの再開の遅れが、U1-NFR2.5（3 秒以内）を守れないため。その代わり費用が常にかかる。
- OQ1 費用の上限（暴走や攻撃のとき）は、通し版では置かない。実際に AWS に作る前の承認のときに、あらためて決める。
- OQ2 **AWS に作る前に、利用者に確認すること**：(a) 概算の月額（上の「費用の目安」）が許容できるか、(b) 接続の束ねを置くか外すか（OQ3）、(c) データベースを止めて費用を下げる代わりに、立ち上がりの遅れを許すか。
- OQ3 接続の束ねは、同時実行を 10 に絞れば不要の見込み。外すと月 20 ドル前後安くなる。実測のうえで決める。
