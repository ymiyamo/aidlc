# 細かい設計（Functional Design）に関する質問：U1 最小の通し版

## この段階で決めること

ここから、作る段階（Construction）です。ユニットごとに、**細かい決めごと**を決めます。今回は、最初のユニット **U1（最小の通し版）**です。これまでに「何を作るか」「どう分けるか」「どの順で作るか」は決まりました。今回は、**データの細かい形と、判断のルール**です。

| 日本語 | 英語 | 意味 |
|---|---|---|
| 機能設計 | Functional Design | データの形、判断のルール、操作の流れを、技術を決めずに設計すること |
| エンティティ | Entity | 覚えておく情報のまとまり（例：料理、メンバー） |
| 業務ルール | Business rule | 「こういうときは、こうする」という決めごと（例：URL は http か https のみ） |
| ユニット | Unit of work | 作る単位。U1 は、ログイン、グループ作成、保存、候補をスワイプで見る |
| 最小の通し版 | Walking skeleton | 端から端まで通しで動く最小の版 |

U1 の内容は、`unit-of-work.md` の U1 の節と、`unit-of-work-story-map.md` にあります。すでに決まっていること（例：URL は http か https のみ、初期データ 30 件、パスワード 8 文字以上、ロックは U7）は、質問しません。

質問ごとに、おすすめの案に **（おすすめ）** を付けました。`[Answer]:` の後ろに選択肢の文字を書いてください。迷う場合は、おすすめで構いません。
