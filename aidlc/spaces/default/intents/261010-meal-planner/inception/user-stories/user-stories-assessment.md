# ユーザーストーリーの要否の評価

## 判断

**Execute（実施する）**

## 理由

- 利用者が直接触れる画面と操作が中心のアプリである（保存、買い物前の候補表示、買い物リスト、記録）。
- 家族グループという複数の立場の利用者がいる（保存する人、見る人、好き嫌い・アレルギーを持つ人）。
- 除外の判定や、候補が足りないときの扱いなど、振る舞いの細かい条件が多く、受け入れ条件を具体的に書く価値がある。

## 検討した要素

- 種類：新規のアプリ（greenfield）
- 利用者向けの範囲：大きい（スマートフォンの画面が中心）
- 複雑さ：中程度（絞り込み、除外、グループ内の共有）

## ストーリーが特に役立つ部分

- 中心機能：保存（FR1）と買い物前の候補表示（FR2）。ここが「やる気を引き出す」体験の核になる。
- 家族の好き嫌い・アレルギーによる除外（FR4）。安全に関わるため、条件を明確にする。
- グループの参加・脱退・削除時のデータの扱い（FR7）。
