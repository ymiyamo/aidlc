# ユーザーストーリー

要件（`requirements.md`）の機能ごと（FR1〜FR7）にグループを作り、次の版以降の機能（FR8〜FR11）は Won't の 1 行ストーリーにしました（Q3 B）。受け入れ条件は操作の合否に絞り、「気持ちへの効果」は最初の版を使ってから別途確かめます（Q4 A）。

優先度：Must / Should / Could / Won't。最初の版（MVP）の境界は、あとの Delivery Planning で決めます。

## グループ 1：おいしそうな出会いを保存する（FR1）

### US1.1 URL と料理名で保存する
- **ストーリー**：見つけて保存する人（P1）として、おいしそうな投稿の URL と料理名だけで保存したい。それは、偶然の出会いを逃さないため。
- **優先度**：Must
- **受け入れ条件**：
  - AC1.1.1 Given ログイン済みである、When URL と料理名を入力して保存する、Then 項目が保存され、一覧に表示される。
  - AC1.1.2 Given 保存した項目がある、When その項目の URL を開く、Then 元の動画・投稿が元のサービスで開く。
  - AC1.1.3 Given http または https 以外の URL を入力した、When 保存しようとする、Then 保存されず、URL の形式が正しくないと表示される。
- **INVEST**：独立して作れ、小さく、操作で確認できる。

### US1.2 保存した項目に詳しい情報を足す
- **ストーリー**：P1 として、保存した項目に調理時間、手間、気分のタグ、材料、メモを足したい。それは、買い物前に状況に合わせて見つけやすくするため。
- **優先度**：Must
- **受け入れ条件**：
  - AC1.2.1 Given 保存した項目がある、When 調理時間（15 分以内、30 分以内、それ以上）、手間（楽、ふつう、頑張れる）、気分のタグ、材料と分量、メモを入力する、Then それらが項目に保存される。
  - AC1.2.2 Given 詳しい情報を入力していない項目がある、When 一覧を開く、Then その項目も通常どおり表示される。

### US1.3 スマートフォンから少ない操作で保存する
- **ストーリー**：P1 として、SNS を見ている途中のスマートフォンから、どの画面にいても少ない操作で保存したい。それは、保存が面倒で出会いを逃さないため。
- **優先度**：Must
- **受け入れ条件**：
  - AC1.3.1 Given スマートフォンで保存の画面を開いた、When URL と料理名を入力する、Then 1 画面の中で保存まで完了できる。
  - AC1.3.2 Given スマートフォンの共有メニューが使えない環境である、When 保存したい、Then URL を貼り付けて保存する方法で保存できる。
  - AC1.3.3 Given どの主な画面（買い物前、保存、献立、記録）を開いていても、When 画面の右下の「＋」を押す、Then 保存の画面が開く。
  - AC1.3.4 Given 「買い物前」の画面を開いている、When 「貼り付けて保存」を押す、Then クリップボードの URL が入った保存の画面が開く。
  - AC1.3.5 Given 共有メニューが使える環境である、When 他のアプリの共有メニューからこのアプリを選ぶ、Then 共有した URL が入った保存の画面が開く。

### US1.5 料理のイメージ画像を見る・登録する
- **ストーリー**：P1 として、料理のイメージが湧く画像を見たい。それは、投稿元に飛ばなくても、おいしそうかどうかが分かるため。自分で画像を登録することもしたい。
- **優先度**：Should
- **受け入れ条件**：
  - AC1.5.1 Given 画像を登録していない項目がある、When 候補または詳細を見る、Then 生成 AI で作った画像が表示され、「AI が作ったイメージ」の印が付く。
  - AC1.5.2 Given 保存または編集の画面を開いた、When 画像（スクリーンショットなど）を登録する、Then 登録した画像が表示され、AI の画像は表示されない。
  - AC1.5.3 Given 5MB を超える画像、または画像でないファイルを選んだ、When 登録しようとする、Then 登録されず、理由が表示される。
  - AC1.5.4 Given 別のグループのメンバーである、When 登録された画像の場所にアクセスする、Then 見られない。

### US1.4 家族と保存した項目を共有する
- **ストーリー**：家族の一員（P2）として、同じグループの人が保存した項目を見たい。それは、家族の「食べたい」を知るため。
- **優先度**：Should
- **受け入れ条件**：
  - AC1.4.1 Given 同じグループの別のメンバーが項目を保存した、When 自分が一覧を開く、Then その項目が表示される。
  - AC1.4.2 Given 別のグループのメンバーである、When 一覧を開く、Then 他のグループの項目は表示されない。

## グループ 2：買い物前に、気分や状況に合わせて見る（FR2）

### US2.1 買い物前に候補を 1 件ずつスワイプで見る
- **ストーリー**：P1 として、買い物前に保存した中から候補を 1 件ずつ大きなカードで見て、スワイプで選ぶかパスしたい。それは、動画を見るような感覚で、作る気持ちが湧くおいしそうなものを選ぶため。
- **優先度**：Must
- **受け入れ条件**：
  - AC2.1.1 Given 保存した項目が 1 件以上ある、When 「買い物前」の画面を開く、Then 1 件が大きなカードで表示される。
  - AC2.1.2 Given 候補のカードが表示されている、When 右にスワイプする（または「これにする」を押す）、Then その項目が「選んだもの」に入り、次の候補が表示される。
  - AC2.1.3 Given 候補のカードが表示されている、When 左にスワイプする（または「パス」を押す）、Then その項目はリセットするまで再び表示されず、次の候補が表示される。
  - AC2.1.4 Given すべての項目を見終えた、When 次の候補を見ようとする、Then 見終えたことが表示され、「最初から見る」が選べる。
  - AC2.1.5 Given ログイン後のホーム画面を開いている、When 「買い物前」の画面を開く、Then 2 回以内の操作で開ける。
  - AC2.1.6 Given スワイプができない環境である、When 候補を見る、Then ボタンだけで、選ぶ・パスのすべての操作ができる。

### US2.2 「今日の気分」で絞り込む
- **ストーリー**：P1 として、横にスクロールするチップではなく、大きな選択肢で調理時間、手間、気分のタグを選んで候補を絞り込みたい。それは、片手でも選びやすく、その日の状況に合うものだけを見るため。
- **優先度**：Must
- **受け入れ条件**：
  - AC2.2.1 Given 絞り込みを指定していない、When 候補を見る、Then 保存した全項目から選ばれる。
  - AC2.2.2 Given 「今日の気分」のシートを開いた、When 調理時間を「15 分以内」にする、Then 「15 分以内」の項目だけが候補になり、該当する件数が表示される。
  - AC2.2.3 Given 調理時間と手間の両方を指定した、When 候補を見る、Then 両方に合う項目だけが表示される。
  - AC2.2.4 Given 「今日の気分」のシートを開いた、When 選択肢を見る、Then 横にスクロールせずに、すべての選択肢が見える。
  - AC2.2.5 Given 「今日の気分」のシートで選んだ、When 「見る」を押す、Then 選んだ条件の候補が最初から表示される。

### US2.5 何も思い浮かばないときに頼る
- **ストーリー**：P1 として、本当に何も思い浮かばないときに、おまかせで出してもらったり、外で探したりしたい。それは、考える負担をさらに減らすため。
- **優先度**：Should
- **受け入れ条件**：
  - AC2.5.1 Given 保存した項目（初期データを含む）が 1 件以上ある、When 「おまかせ」を押す、Then 絞り込みなしで、保存した項目から 1 件がランダムに表示される。
  - AC2.5.2 Given 「今日の気分」で調理時間と気分を選んでいる、When 「外で探す」を押す、Then 選んだ気分・調理時間のキーワードが入った YouTube（または Instagram）の検索画面が開く。
  - AC2.5.3 Given 「外で探す」で検索画面が開いた、When 検索結果を見る、Then アプリが結果を取り込むことはない（検索画面を開くだけ）。

### US2.6 選んだものから買い物リストにつなぐ
- **ストーリー**：P1 として、「これにする」で選んだ料理の材料を、そのまま買い物リストに入れたい。それは、選んだあとに別の操作をしなくて済むため。
- **優先度**：Must
- **受け入れ条件**：
  - AC2.6.1 Given 「これにする」で項目を選んだ、When 「選んだもの」を見る、Then 選んだ項目が一覧になる。
  - AC2.6.2 Given 「これにする」で項目を選んだ、When 買い物リストを開く、Then その項目の材料が追加されている。
  - AC2.6.3 Given 選んだものを外した、When 買い物リストを開く、Then その項目の材料が外れている。

### US2.3 家族が食べられないものを候補から外す
- **ストーリー**：P2 として、自分が食べられない食材を含む料理が、候補に出ないでほしい。それは、見ていて嫌な気持ちにならず、安全でいるため。
- **優先度**：Must
- **受け入れ条件**：
  - AC2.3.1 Given 家族の誰かが「えび」を除外に登録している、When 材料に「えび」を含む項目がある、Then その項目は候補に表示されない。
  - AC2.3.2 Given 材料が未入力の項目がある、When 候補に表示される、Then 「材料が未入力」と明示して表示される。

### US2.4 候補がないときに案内される
- **ストーリー**：P1 として、候補がないときに次にすることを知りたい。それは、行き止まりにならないため。
- **優先度**：Should
- **受け入れ条件**：
  - AC2.4.1 Given 保存した項目が 0 件である、When 「買い物前」の画面を開く、Then 「まだ保存がありません」と保存の方法の案内が表示される。
  - AC2.4.2 Given 絞り込みの結果が 0 件である、When 候補を見る、Then 絞り込みを緩めるよう案内が表示される。

## グループ 3：作るものを選んで買い物リストにする（FR3）

### US3.1 選んだ料理から買い物リストを作る
- **ストーリー**：P1 として、作るものを選んで、必要な材料の買い物リストを作りたい。それは、買い物の準備の手間を減らすため。
- **優先度**：Should
- **受け入れ条件**：
  - AC3.1.1 Given 複数の項目を選んだ、When 買い物リストを作る、Then 選んだ項目の材料が一覧になる。
  - AC3.1.2 Given 同じ材料で単位も同じものが複数ある、When リストを作る、Then 分量が合算されて 1 行になる。
  - AC3.1.3 Given 同じ材料で単位が異なる、When リストを作る、Then 別の行として表示される。
  - AC3.1.4 Given 材料が未入力の項目を選んだ、When リストを作る、Then その項目に「材料の入力が必要」と表示される。
  - AC3.1.5 Given 材料が 1 件もない、When リストを開く、Then リストが空であることが表示される。

### US3.2 買い物中にチェックを付ける
- **ストーリー**：P1 として、買ったものにチェックを付けたい。それは、買い忘れ・買い過ぎを防ぐため。
- **優先度**：Should
- **受け入れ条件**：
  - AC3.2.1 Given 買い物リストがある、When 材料にチェックを付ける、Then チェックが保存され、再表示してもチェックが残る。
  - AC3.2.2 Given スマートフォンで開いた、When リストを見る、Then 横にスクロールせずに読める。

## グループ 4：家族の好き嫌い・アレルギー（FR4）

### US4.1 好き嫌いを登録する
- **ストーリー**：P2 として、自分の嫌いな食材を登録したい。それは、毎回口で伝えなくても、候補や献立から外してほしいため。
- **優先度**：Must
- **受け入れ条件**：
  - AC4.1.1 Given ログイン済みである、When 嫌いな食材を登録する、Then 自分の登録として保存される。
  - AC4.1.2 Given 家族のメンバーの誰かが嫌いな食材を登録した、When 候補または献立を作る、Then その食材を含む項目は外される。

### US4.2 アレルギーの扱い（FR13）
- **ストーリー**：P2 として、アレルギーのある食材を登録し、どんな条件でも提案に出ないようにしたい。それは、安全に使うため。
- **優先度**：Won't（最初の実装では作らない。次の版以降で検討する）
- **備考**：食材名の表記ゆれ（「えび」「海老」「エビ」など）の正規化も、最初の実装では行わない。

### US4.3 食材名は文字列の一致で照合する
- **ストーリー**：P2 として、登録した嫌いな食材が、材料の文字列と一致したときに外れてほしい。それは、最小の仕組みで好き嫌いを反映するため。
- **優先度**：Must
- **受け入れ条件**：
  - AC4.3.1 Given 嫌いな食材として「えび」を登録した、When 材料に「えび」と書かれた項目がある、Then その項目は候補・献立から外れる。
  - AC4.3.2 Given 嫌いな食材として「えび」を登録した、When 材料に「海老」と書かれた項目がある、Then その項目は外れない（表記ゆれの正規化はしない）。

## グループ 5：1 週間の献立の提案（FR5）

### US5.1 1 週間の献立を提案させる
- **ストーリー**：P1 として、保存した項目から 1 週間（7 日分）の献立の提案を作らせたい。それは、毎日考える手間を減らすため。
- **優先度**：Must（US5.2 の「やり直し」が提案を前提とするため、Could から引き上げた）
- **受け入れ条件**：
  - AC5.1.1 Given 条件を満たす項目が 7 件以上ある、When 提案を作る、Then 7 日分の献立が表示される。
  - AC5.1.2 Given 提案を作った、When 内容を見る、Then 同じ料理が 1 週間に 3 回以上含まれない。
  - AC5.1.3 Given 提案を作った、When 内容を見る、Then 食材の種類が同じ日が 3 日続かない。
  - AC5.1.4 Given 家族の誰かが除外した食材がある、When 提案を作る、Then その食材を含む料理は含まれない。
  - AC5.1.5 Given 保存した項目が 200 件以下である、When 提案を作る、Then 3 秒以内に結果が表示される。

### US5.2 提案をやり直す
- **ストーリー**：P1 として、日ごと、または週全体を別案に変えたい。それは、気に入らない提案を受け入れなくて済むため。
- **優先度**：Must
- **受け入れ条件**：
  - AC5.2.1 Given 提案が表示されている、When ある日を「やり直し」する、Then その日だけが別の料理に変わる。
  - AC5.2.2 Given 提案が表示されている、When 週全体を「やり直し」する、Then 7 日分が別の組み合わせに変わる。

### US5.3 候補が足りないときの表示
- **ストーリー**：P1 として、条件に合う料理が足りないときの状況を知りたい。それは、なぜ空欄なのか分かり、次にすることが決められるため。
- **優先度**：Could
- **受け入れ条件**：
  - AC5.3.1 Given 条件を満たす料理が 7 件に満たない、When 提案を作る、Then 足りない日は空欄になり、理由と料理を保存する案内が表示される。

### US5.4 提案を保存して使う
- **ストーリー**：P1 として、作った提案を保存し、あとで呼び出して使いたい。それは、気に入った組み合わせを繰り返し使うため。
- **優先度**：Could
- **受け入れ条件**：
  - AC5.4.1 Given 提案が表示されている、When 保存する、Then 保存した提案の一覧に追加される。
  - AC5.4.2 Given 保存した提案がある、When 呼び出す、Then そのまま、または一部を変更して使える。

### US5.5 「この日は作らない」を設定・解除する
- **ストーリー**：P1 として、献立の日ごとに「この日は作らない」を設定し、あとから消したい。それは、外食や惣菜の日を最初から除いて、現実に合う献立にするため。
- **優先度**：Must
- **受け入れ条件**：
  - AC5.5.1 Given 献立が表示されている、When ある日に「この日は作らない」を設定する、Then その日は「作らない」と表示され、料理が割り当てられない。
  - AC5.5.2 Given 「作らない」の日がある、When 買い物リストを作る、Then その日の料理の材料は含まれない。
  - AC5.5.3 Given 「作らない」の日がある、When 候補が足りない日の数を数える、Then その日は「空き」に数えない。
  - AC5.5.4 Given 「作らない」の日がある、When その設定を消す（解除する）、Then その日はふつうの日に戻り、料理を提案させられる。

### US5.6 買い物前で選んだものを献立に使う
- **ストーリー**：P1 として、買い物前で選んだものを、1 週間の献立の日に割り当てたい。それは、買い物前の画面と献立がつながり、選んだものが無駄にならないため。
- **優先度**：Should
- **受け入れ条件**：
  - AC5.6.1 Given 「選んだもの」が 1 件以上ある、When 献立の画面を開く、Then 「選んだもの」が、日に割り当てる候補として表示される。
  - AC5.6.2 Given 「選んだもの」の項目を、ある日に割り当てた、When 献立を見る、Then その日にその料理が表示される。

## グループ 6：お気に入りと作った記録（FR6）

### US6.1 お気に入りにする
- **ストーリー**：P1 として、気に入った項目をお気に入りにしたい。それは、あとで探しやすくするため。
- **優先度**：Should
- **受け入れ条件**：
  - AC6.1.1 Given 項目の詳細を開いている、When お気に入りにする、Then お気に入りの一覧に表示される。

### US6.2 項目の詳細から、作った日を記録する（1 つの項目に何回でも）
- **ストーリー**：P2 として、項目の詳細から「作った日」を追加し、感想（また作りたいか、もう作りたくないか）と、料理中の注意点のメモを残したい。同じ料理を何回作っても、作った日ごとに残したい。それは、次に選ぶときと、次に作るときの手がかりにするため。
- **優先度**：Must
- **受け入れ条件**：
  - AC6.2.1 Given 項目の詳細を開いている、When 「作った日を追加」を押す、Then 作った日（初期値は今日）を選ぶパネルが開く。
  - AC6.2.2 Given 作った日を選んだ、When 感想（「また作りたい」または「もう作りたくない」）を選ぶ、Then 選んだ感想が、その作った日の記録として保存される。感想は選ばなくてもよい。
  - AC6.2.3 Given 作った日のパネルを開いている、When 料理中の注意点をメモに入力して保存する、Then メモが、その作った日の記録として保存される。メモは空でもよい。
  - AC6.2.4 Given 同じ項目に作った日が複数ある、When その項目の詳細を開く、Then 作った回数と、作った日の一覧（日付の新しい順、各回の感想とメモ）が表示される。
  - AC6.2.5 Given 作った日の記録がある、When その記録の感想・メモ・日付を変更して保存する、Then 新しい内容に置き換わる。
  - AC6.2.6 Given 作った日の記録がある、When その記録を削除する（確認のあと）、Then その記録だけが削除され、同じ項目の他の記録は残る。
  - AC6.2.7 Given 作った日のパネルを開いている、When 未来の日付を選ぼうとする、Then 選べない（今日までの日付のみ）。
  - AC6.2.8 Given 同じ項目に同じ日の記録がすでにある、When 同じ日で追加しようとする、Then すでに記録があることが表示され、既存の記録の編集が案内される。

### US6.4 作った記録をカレンダーで見る
- **ストーリー**：P2 として、作った記録を月のカレンダーでも見たい。それは、いつ何を作ったかを、日付の並びでつかむため。日をタップしなくても内容が分かってほしい。
- **優先度**：Should
- **受け入れ条件**：
  - AC6.4.1 Given 記録がある、When 記録の画面でカレンダーを開く、Then 作った日に、料理名（短く）と感想の印（また作りたい／もう作りたくない）が表示される。
  - AC6.4.2 Given カレンダーを開いている、When カレンダーの下を見る、Then その月の記録が一覧で表示される。
  - AC6.4.3 Given カレンダーを開いている、When 日をタップする、Then その日の記録の一覧（料理・感想・注意点メモ）と、「作ったものを追加」ボタンが表示される（記録のない日でも表示される）。
  - AC6.4.4 Given 記録の画面を開いた、When 「一覧」と「カレンダー」を切り替える、Then それぞれの表示に変わる。
  - AC6.4.5 Given 1 日に複数の料理を作った、When カレンダーを見る、Then その日に複数あることが分かる表示になる。

### US6.5 カレンダーの日付から、作ったものを追加する
- **ストーリー**：P2 として、記録のカレンダーで日付をタップして、その日に作ったものを選んで追加したい。それは、作った日をあとからでも、カレンダーを見ながら簡単に残せるようにするため。
- **優先度**：Should（登録の入口の検討中。OQ11、OQ12）
- **受け入れ条件**：
  - AC6.5.1 Given 記録のカレンダーを開いている、When 日付をタップして「作ったものを追加」を押す、Then 保存した項目（初期データを含む）を選ぶ画面が開く。
  - AC6.5.2 Given 項目を選ぶ画面を開いている、When 料理名で絞り込む、または「最近選んだもの」「お気に入り」「すべて」を切り替える、Then 該当する項目が表示される。
  - AC6.5.3 Given 項目を選んだ、When 感想と注意点メモを入力して（どちらも任意）保存する、Then その日の記録として追加され、カレンダーのその日に料理名と感想の印が出る。
  - AC6.5.4 Given 同じ日に、すでに別の項目の記録がある、When 続けて別の項目を追加する、Then 同じ日に複数の記録が並ぶ。
  - AC6.5.5 Given 未来の日付をタップした、When 「作ったものを追加」を押そうとする、Then 追加できない（今日までの日付のみ）ことが表示される。
  - AC6.5.6 Given 作ったものが保存した項目にない、When 追加の画面で探す、Then 「保存する」の画面へ案内される。

### US6.6 追加した記録を編集・削除する
- **ストーリー**：P2 として、登録した作った日の記録を、あとから直したり消したりしたい。それは、日付や感想の間違いに気づいたとき、直せるようにするため。
- **優先度**：Should
- **受け入れ条件**：
  - AC6.6.1 Given カレンダーのその日の一覧を開いている、When 記録を選んで編集する、Then 日付・感想・注意点メモを変更して保存できる。
  - AC6.6.2 Given カレンダーのその日の一覧を開いている、When 記録を削除する（確認のあと）、Then その記録だけが削除され、カレンダーの表示も更新される。

### US6.3 「もう作りたくない」ものを後ろにずらす
- **ストーリー**：P1 として、「もう作りたくない」と記録した項目が候補の後ろに出てほしい。それは、期待外れだったものを何度も見ないため。
- **優先度**：Should
- **受け入れ条件**：
  - AC6.3.1 Given 最新の記録の感想が「もう作りたくない」である項目がある、When 候補を見る、Then その項目は、記録のない項目・最新の感想が「また作りたい」の項目より後に表示される。
  - AC6.3.2 Given 同じ項目に、以前は「もう作りたくない」、最新は「また作りたい」の記録がある、When 候補を見る、Then 最新の記録（また作りたい）が使われ、後ろにずらされない。

## グループ 7：アカウントと家族グループ（FR7）

### US7.1 アカウントを作ってログインする
- **ストーリー**：P1 として、アカウントを作ってログインしたい。それは、複数の端末で同じ内容を使うため。
- **優先度**：Must
- **受け入れ条件**：
  - AC7.1.1 Given アカウントを持っていない、When 登録する、Then ログインして使い始められる。
  - AC7.1.2 Given パスワードを忘れた、When 再設定の手続きをする、Then 新しいパスワードでログインできる。
  - AC7.1.3 Given ログインに 5 回続けて失敗した、When 6 回目を試す、Then 15 分間ログインできない。

### US7.2 家族グループを作って招待する
- **ストーリー**：P1 として、家族グループを作り、招待リンクで家族を招待したい。それは、家族と同じ内容を共有するため。
- **優先度**：Must
- **受け入れ条件**：
  - AC7.2.1 Given ログイン済みである、When グループを作り招待リンクを発行する、Then 招待リンクが表示される。
  - AC7.2.2 Given 招待リンクを受け取った、When 7 日以内にリンクを開いて参加する、Then グループのメンバーになり、共有内容が見られる。
  - AC7.2.3 Given 招待リンクの発行から 7 日を過ぎた、When リンクを開く、Then 参加できず、再発行が必要と表示される。

### US7.3 グループから抜ける
- **ストーリー**：P2 として、グループから抜けたい。それは、家族の状況が変わったときに抜けられるため。
- **優先度**：Should
- **受け入れ条件**：
  - AC7.3.1 Given グループのメンバーである、When 抜ける、Then 自分の好き嫌いの登録が提案の条件から外れる。
  - AC7.3.2 Given 自分が保存した項目と記録がある、When 抜ける、Then それらはグループに残る。

### US7.4 アカウントを削除する
- **ストーリー**：P2 として、アカウントを削除したい。それは、個人情報を残したくなくなったときに消せるため。
- **優先度**：Should
- **受け入れ条件**：
  - AC7.4.1 Given アカウントを持っている、When 削除する、Then メールアドレスと好き嫌いの登録が削除される。
  - AC7.4.2 Given 自分が保存した項目と記録がある、When アカウントを削除する、Then それらはグループに残り、保存した人の名前は表示されない。

### US7.5 最後の 1 人が抜けたらグループを消す
- **ストーリー**：P1 として、誰もいなくなったグループのデータが残らないでほしい。それは、不要な個人情報を残さないため。
- **優先度**：Could
- **受け入れ条件**：
  - AC7.5.1 Given メンバーが 1 人だけのグループである、When その人が抜ける、Then そのグループのデータが削除される。

## グループ 9：初期データ（FR12）

### US9.1 無難な料理 30 件が最初から入っている
- **ストーリー**：P1 として、最初から無難な料理が 30 件入っていてほしい。それは、保存が少ない最初の段階でも、候補と献立の提案が足りなくならないため。
- **優先度**：Must
- **受け入れ条件**：
  - AC9.1.1 Given 新しい家族グループを作った、When 保存した項目の一覧を開く、Then 初期データの料理 30 件が表示される。
  - AC9.1.2 Given 初期データの料理がある、When その項目の URL を確認する、Then ダミーの URL が設定されている。
  - AC9.1.3 Given 初期データの内容を別の内容に入れ替えたい、When 開発時にデータファイルの内容を差し替える、Then プログラムを変更せずに、新しいグループに差し替えた内容が登録される。
  - AC9.1.4 Given 初期データの料理がある、When 項目を編集または削除する、Then その変更が反映される（グループごとの複製である）。
  - AC9.1.5 Given 初期データの料理だけがある（利用者の保存が 0 件）、When 「買い物前」の画面を開く、Then 候補が表示される。
  - AC9.1.6 Given 初期データの料理だけがある、When 1 週間の献立を提案させる、Then 7 日分が空欄なしで表示される。
  - AC9.1.7 Given 初期データの料理がある、When 候補を見る、Then 生成 AI で作った画像が表示され、「AI が作ったイメージ」の印が付く。
  - AC9.1.8 Given 初期データの画像を差し替えたい、When 開発時にデータファイルと画像を差し替える、Then プログラムを変更せずに、新しいグループに反映される。
