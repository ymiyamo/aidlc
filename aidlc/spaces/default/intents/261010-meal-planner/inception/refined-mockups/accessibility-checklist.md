# アクセシビリティのチェックリスト

目標は WCAG 2.1 の AA [Q7 A]。ここでは設計の段階で確認できる項目を挙げます。実際の達成の確認には、支援技術（スクリーンリーダーなど）を使った手作業のテストと、専門家による確認が必要です。ここでの確認は、その代わりにはなりません。

状態：設計済み＝設計に反映した、実装時に確認＝実装の段階で測る・試す。

## 見た目

| 項目 | 内容 | 状態 |
|---|---|---|
| 文字のコントラスト | 本文は 4.5:1 以上、大きな文字は 3:1 以上 | 実装時に確認（色の目安は `design-system-mapping.md`） |
| 部品のコントラスト | 枠線やアイコンは背景に対して 3:1 以上 | 実装時に確認 |
| 色だけに頼らない | 選択中・エラー・チェック済みに、印（✓、アイコン、文字）を付ける | 設計済み |
| 文字の大きさ | 本文 16px 以上。ブラウザの文字拡大に追随する（200% まで崩れない） | 設計済み／実装時に確認 |
| 画面の向き | 縦向きを基本とし、横向きでも内容を読める | 実装時に確認 |

## 操作

| 項目 | 内容 | 状態 |
|---|---|---|
| 押せる部分の大きさ | 44px × 44px 以上 | 設計済み |
| キーボード操作 | すべての操作が、キーボードだけでできる | 実装時に確認 |
| フォーカスの表示 | フォーカスがどこにあるか、見て分かる | 実装時に確認 |
| フォーカスの順序 | 画面の読み順と一致する | 実装時に確認 |
| パネル・ダイアログ | 開いたらフォーカスを中に移し、閉じたら元に戻す。背景は操作できない | 設計済み |
| スワイプの代わり | スワイプでできる操作（選ぶ、パス）は、すべてボタンでもできる（NFR1.5） | 設計済み |
| 画像の代替の文字 | 画像に説明の文字を付け、AI の画像には「AI が作ったイメージ」と読み上げで伝える | 設計済み |
| カレンダー | 日ごとの料理名と印を、文字でも読み上げられる。色だけで感想を伝えない（♥／✕ と文字） | 実装時に確認 |
| タイムアウト | 時間切れで操作が失われない（通知は消えるが、結果は画面に残る） | 設計済み |

## 支援技術（スクリーンリーダー）

| 項目 | 内容 | 状態 |
|---|---|---|
| ラベル | 入力欄とボタンに、目的が分かるラベルを付ける（アイコンだけのボタンにも名前を付ける） | 設計済み |
| 見出し | 画面の名前と区切りを、見出しとして伝える | 実装時に確認 |
| 状態の通知 | 保存、エラー、候補の入れ替えなどの結果を、読み上げで伝える | 実装時に確認 |
| 選択状態 | チップ、タブ、お気に入りの選択状態を、読み上げで伝える | 実装時に確認 |
| 画像代わりの記号 | ♡／♥／🛒 などには、文字の名前を付ける | 設計済み |

## 入力とエラー

| 項目 | 内容 | 状態 |
|---|---|---|
| エラーの示し方 | どの欄が、なぜ誤りか、入力欄の近くに文章で示す | 設計済み |
| 入力の補助 | メール・パスワード・URL の入力欄に、適切な入力の種類と補助を付ける | 実装時に確認 |
| 取り消せない操作 | 確認のダイアログで、結果を説明する | 設計済み |

## 達成の確認について

- 実装後に、自動の検査ツールで機械的に測れる項目（コントラスト、ラベルの有無など）を確認する。
- スクリーンリーダー（スマートフォンの標準機能など）で、主要な流れ（保存、買い物前、感想の記録）を手作業で確かめる。
- 専門家による確認は、公開（NFR7 の本番デプロイ）の前に実施するかどうかを、あとの段階で決める。
