# 部品の分け方（ドメイン設計）に関する質問

要件・ユーザーストーリー・画面設計をもとに、「自分たちで書くコードの単位（部品）」の分け方を決めます。データベースや外部サービス（YouTube、生成 AI など）は、部品が使うもので、部品そのものではありません。どう配置してデプロイするかは、次の Units Generation で決めます。

質問ごとに、おすすめの案に **（おすすめ）** を付けました。`[Answer]:` の後ろに選択肢の文字を書いてください。

## 前提として、私が分けた部品の案（8 つ）

| 部品 | 担当すること（持つデータ） |
|---|---|
| Account（アカウント） | 登録・ログイン・パスワード再設定・ログイン失敗の制限（アカウント） |
| Household（家族グループ） | グループ・メンバー・招待リンク・脱退・削除、メンバーごとの好き嫌い（グループ、メンバー、招待、嫌いな食材） |
| Dish（料理） | 保存した項目・初期データ・お気に入り・条件・材料・URL・画像の登録（項目、材料、お気に入り） |
| ImageGen（画像づくり） | 登録画像がない項目の AI の画像づくりと保管（生成した画像） |
| Suggestion（候補の提案） | 買い物前の候補（絞り込み、除外、並び順、パス、おまかせ、外で探す用のキーワード）、選んだもの |
| MealPlan（献立） | 1 週間の献立、やり直し、作らない日、保存した献立 |
| ShoppingList（買い物リスト） | 材料の集計、チェック |
| CookLog（作った記録） | 項目と作った日の 1:n の記録、感想、注意点メモ、カレンダー用の集計 |

## Q5. 候補の並べ方と除外の判定は、どこに置きますか？
