# ボルトの計画（Bolt Plan）

**ボルト（Bolt）** とは、作る段階（Construction）での、1 回の作業のまとまり。1 つ以上のユニット（作る単位）を作り、最後は動くものが残る。ここでは、7 つのユニット（U1〜U7）を、どの順で、どのボルトに入れるかを決める。

このファイルだけを開いても分かるよう、用語をここで説明する。

| 日本語 | 英語 | 意味 |
|---|---|---|
| ボルト | Bolt | 1 回の作業のまとまり。動くものが残って終わる |
| ユニット | Unit of work | 作る単位（U1〜U7）。内容は `units-generation/unit-of-work.md` |
| 最小の通し版 | Walking skeleton | 端から端まで通しで動く最小の版。最初に作って、つながりを確かめる |
| 完了の定義 | Definition of Done | そのボルトが終わったと言える条件 |
| 確信の仮説 | Confidence hypothesis | そのボルトを作って動かすと、何が確かめられるかの見立て |
| 最初の版 | MVP | 最初に使ってもらえる、必要最小限の版 |

## Assumptions & Open Questions

- [assumption] ボルトの大きさは、1 つのユニットが 1 つのボルト（Q3 A）。
- [assumption] 同時に作れるところは、同時に作る（Q4 B、Q8 B）。ただし、U1（最小の通し版）だけは、これまでの方針どおり、先に 1 つで作って確認する。進め方の設定（段階ごと、並行して作る）は、エンジンに記録した。
- [assumption] 最初の版（MVP）は、U1〜U5 と U7（Q5 A）。U6（画像）は、次の版。
- [assumption] 確認のコマンド（テストの実行など）は、使う技術をまだ決めていないため、保留（Q9 A）。仮のコマンドは入れない。最初の確認のときに、改めて決める。
- [assumption] 作るのは、この 1 つのセッションの AI。人は、各ボルトの確認と承認をする（Q10 A）。
- OQ1 エンジンは、依存の図にあるすべてのユニット（U6 を含む）を、作る対象とみなす。U6 を最初の版から外す方法（Construction の開始時に、作る範囲から外す、または U6 を最後に回して、着手前に止める）を、Construction の開始時に確認する。
- OQ2 使う技術（言語、道具、ホスティング）は未決定。次の工程（NFR の段階、インフラの段階）で決める。確認のコマンドも、そのあとに決める。
- OQ3 「作った記録」「候補の並び」などの細かい挙動の確認は、各ユニットの機能設計（Functional Design）で行う。

## 作る順番（案）

依存（U3 は U2 の後、U4 は U2・U3 の後）を守る。依存がないものは、同時に作る（Q4 B）。

| 段 | ボルト | ユニット | 同時に作れる相手 | 備考 |
|---|---|---|---|---|
| 1 | B1 | U1 最小の通し版 | なし（先に 1 つで作る） | 最小の通し版。人の承認を別に取る |
| 2 | B2 | U2 好き嫌いと絞り込み | B3、B4 | |
| 2 | B3 | U5 作った記録 | B2、B4 | |
| 2 | B4 | U7 グループとアカウントの管理 | B2、B3 | |
| 3 | B5 | U3 買い物リスト | なし（B2 の後） | |
| 4 | B6 | U4 献立 | なし（B2、B5 の後） | |
| 最初の版の外 | B7 | U6 画像 | | 次の版（OQ1） |

- 段 2 の 3 つ（B2、B3、B4）は、お互いに依存がなく、U1 の後なら、同時に作れる。
- 価値の大きい順（Q2 A）は、U2 → U3 → U5 → U4 → U7 → U6。同時に作れる数に限りがあるときは、この順で優先する。

## B1：最小の通し版（U1）

- **最小の通し版か**：はい。チームの方針（最初に通し版）のとおり。
- **含むユニット**：U1
- **証明すること（どの部品のつながりか）**：画面 → サーバー（REST）→ 料理・家族グループ・アカウント・候補の提案 → データベース。リクエストの入口の所属確認（ADR-005）と、出来事の最小の仕組み（ADR-007）。
- **完了の定義**：
  - ログイン、グループ作成（初期データ 30 件が入る）、URL と料理名の保存ができる。
  - 買い物前の画面で、候補を 1 件ずつ見て、スワイプまたはボタンで「これにする」「パス」ができ、見終えたときと保存が 0 件のときの案内が出る。
  - 他のグループの項目の ID を渡しても、何も届かない（所属確認のテスト）。
  - US7.1、US7.2（グループ作成）、US9.1、US1.1〜US1.4、US2.1、US2.4（保存 0 件）、US6.1 の受け入れ条件を満たす。
  - 初期データは、データファイルとして、プログラムと別に持ち、入れ替えられる。
- **確信の仮説**：「出会いを保存して、買い物前に 1 件ずつスワイプで見る」流れが、気持ちよく動き、作る気持ちを引き出す。
- **期待するデモ**：新規登録 → グループを作る（30 件が入る）→ 投稿の URL と料理名を保存 → 買い物前の画面でスワイプして候補を見る → 「これにする」。
- **確認の方法**：端から端までを動かして確かめる。確認のコマンドは保留（Q9 A）なので、最初の確認のときに、使う技術が決まったうえで決める。

## B2：好き嫌いと絞り込み（U2）

- **含むユニット**：U2
- **完了の定義**：嫌いな食材の登録・削除、「今日の気分」での絞り込み、除外（文字列の一致）、材料が未入力の項目の表示、おまかせ、外で探す、絞り込み 0 件の案内。US4.1、US4.3、US2.2、US2.3、US2.4（絞り込み 0 件）、US2.5 の受け入れ条件を満たす。
- **確信の仮説**：家族の好き嫌いが反映されると、嫌いなものが出ず、安心して候補を見られる。気分の絞り込みが、片手で選びやすい。
- **期待するデモ**：嫌いな食材を登録 → 該当する料理が候補から外れる。「今日の気分」で絞り込み、件数が変わる。

## B3：作った記録（U5）

- **含むユニット**：U5
- **完了の定義**：項目の詳細と、カレンダーの日付から、作った日を追加（未来の日は不可、同じ日の同じ項目は二重に登録しない）。感想と注意点メモ。記録の編集・削除。カレンダーと一覧。「もう作りたくない」の項目を候補の後ろにずらす。US6.2〜US6.6 の受け入れ条件を満たす。
- **確信の仮説**：日付から記録を足す操作が、面倒でなく続けられ、記録が次の選ぶときの手がかりになる。
- **期待するデモ**：カレンダーで日付を押す → 作ったものを追加 → カレンダーに料理名と印が出る。

## B4：グループとアカウントの管理（U7）

- **含むユニット**：U7
- **完了の定義**：招待リンク（7 日間有効）と参加、脱退（その人の好き嫌いを外す）、アカウント削除（退会したメンバーの扱い）、パスワード再設定、ログイン失敗の制限（5 回で 15 分）、グループ削除（暫定の案）。US7.1（再設定、制限）、US7.2（招待、参加）、US7.3、US7.4、US7.5 の受け入れ条件を満たす。
- **確信の仮説**：家族が招待リンクで参加でき、同じ保存した項目を見られる。
- **期待するデモ**：招待リンクを発行 → 別の端末で参加 → 同じ項目が見える。

## B5：買い物リスト（U3）

- **含むユニット**：U3
- **完了の定義**：選んだものの材料を集計（同じ材料・同じ単位は合算）、材料が未入力の項目の案内、チェックの付け外しと保存。US2.6、US3.1、US3.2 の受け入れ条件を満たす。
- **確信の仮説**：「これにする」を押すだけで、買い物の準備が済む。
- **期待するデモ**：数件を「これにする」で選ぶ → 買い物リストに材料がまとまる → 買い物中にチェックを付ける。

## B6：献立（U4）

- **含むユニット**：U4
- **完了の定義**：1 週間（7 日分）の提案（同じ料理は週 2 回まで、同じ食材の種類は 3 日続けない）、やり直し（日ごと、週全体）、この日は作らない（設定・解除）、選んだものの割り当て、献立の保存と呼び出し、候補が足りない日の表示、この献立の買い物リスト（買い物リストに材料を渡す）。US5.1〜US5.6 の受け入れ条件を満たす。
- **確信の仮説**：1 週間の献立が、手間なく決まり、現実（外食の日）に合わせられる。
- **期待するデモ**：1 週間の献立を作る → 水曜を「作らない」にする → 買い物リストに、作らない日の材料が入らない。

## B7：画像（U6）— 最初の版の外

- **含むユニット**：U6
- **完了の定義（次の版で）**：登録した画像（5MB 以下）、AI の画像（登録がないとき）、「AI が作ったイメージ」の印、初期データ 30 件の画像。US1.5 と、US9.1 の画像の受け入れ条件を満たす。
- **確信の仮説**：画像があると、おいしそうかどうかが、投稿元に行かなくても分かる。
- **先に決めること**：生成 AI のサービス、費用と回数の上限、安全面（要件の OQ7）。
- **備考**：最初の版では、画像がない項目に、色の枠を出す（B1 の時点で動く）。
